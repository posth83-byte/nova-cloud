# NOVA Studio Engine — architecture and acceptance plan

## Goal

Build a first-party production pipeline that does not call ChatGPT image/video generation quotas or paid generation APIs. JARVIS/NOVA submits a project; a worker that we control creates the assets and final MP4.

This is an orchestration and rendering system, not a claim that a free model can reproduce Pixar's proprietary quality. The target is an original, polished family-animation look.

## Architecture

1. **NOVA Cloud control plane (Render)**
   - Accepts a project brief, aspect ratio, duration, style and output options.
   - Stores durable job state and progress in Supabase.
   - Issues short-lived work leases to an authenticated worker.
   - Stores finished MP4, subtitle and project metadata in the existing private storage bucket.
   - Keeps the existing procedural renderer as a no-model fallback.

2. **NOVA Studio Worker (Windows PC)**
   - Runs as a user-controlled background process and polls the cloud for work.
   - Does not expose the home PC to inbound internet traffic.
   - Talks to a local ComfyUI API at 127.0.0.1 only.
   - Submits storyboard/image-generation workflows, waits for outputs, assembles scenes with FFmpeg, and uploads artifacts.
   - Reports heartbeats, progress and errors. A worker lease can expire safely if the PC disconnects.

3. **Free local generation stack**
   - ComfyUI as the local workflow host; use compatible open model weights and document each model's license.
   - Start with a low-VRAM Stable Diffusion 1.5 workflow that can run within a 6 GB GPU budget; keep resolution and batch size conservative.
   - Use image-to-video / frame interpolation only as an optional later stage. The initial release must work without it.
   - FFmpeg handles editing, audio mix, subtitles and MP4 encoding.
   - Swedish narration remains a separate speech adapter; do not make it a dependency of image generation.

## Job lifecycle

queued -> leased -> generating -> assembling -> uploading -> completed

Recoverable failures:
- Worker offline: lease expires and job returns to queued.
- ComfyUI unavailable/model missing: report a clear setup error; do not silently claim a successful render.
- Upload interrupted: retry with bounded backoff and verify the stored object.
- Unsupported model/workflow: reject before spending GPU time.

## Security

- Worker token is stored only in Render environment variables and the local worker config; never in browser code or Git.
- Worker endpoints require constant-time token comparison.
- The worker makes outbound HTTPS requests only; no public inbound port on the user's PC.
- Project prompts and generated files are treated as untrusted input; filenames are generated by the server.
- Supabase service credentials remain server-side.

## Phased delivery

### Phase 1 — foundation
- Define durable job contract and worker protocol.
- Add authenticated claim/heartbeat/result endpoints.
- Add local worker client with health checks and ComfyUI connectivity test.
- Keep the current procedural engine unchanged as fallback.

### Phase 2 — local image pipeline
- Add a versioned ComfyUI workflow template with prompt placeholders.
- Generate storyboard frames and validate output dimensions/file types.
- Add safe retries and per-scene progress.

### Phase 3 — film assembly
- Add consistent character references, scene sequencing, camera motion, Swedish voice, SRT and final MP4.
- Add a project manifest so a film can be re-rendered without repeating successful stages.

### Phase 4 — verification
- End-to-end test from JARVIS UI through Render -> local worker -> ComfyUI -> MP4 upload.
- Verify MP4 decoding, audio, subtitles, dimensions, storage retrieval and worker-offline recovery.
- Only mark the engine ready after a real end-to-end test passes.

## Acceptance criteria

- No calls to OpenAI image/video generation or paid generation APIs.
- The cloud service can queue a project while the worker is offline.
- A connected local worker can claim and finish a job.
- A completed job returns a playable MP4 and subtitle file from private storage.
- A failed or disconnected worker never produces a false completed status.
- Existing procedural video smoke test continues to pass.

## Important operating constraint

The cloud control plane can queue and store work, but the local GPU worker must be powered on and connected for local AI generation. This avoids hosted inference quotas; it does not make GPU computation free or available while the PC is off.
